# Маршрут.Док

**Локальная система для работы со сбоями общественного транспорта.** Диспетчер вводит сообщение, проверяет анализ происшествия и похожие случаи, выбирает меру, согласует решение и скачивает редактируемые DOCX.

**Для обычного запуска нужен только Python.** Готовый интерфейс уже лежит в `frontend/dist`; устанавливать Node.js и собирать сайт не требуется. Приложение работает на вашем компьютере, без внешних API и языковых моделей.

| Что есть в приложении | Как работает |
| --- | --- |
| Классификация сообщения | Настоящее обучение `TF-IDF + LogisticRegression` через `fit()`, сохранение и загрузка модели |
| Похожие случаи | Поиск по TF-IDF и косинусному сходству в локальном учебном реестре |
| Варианты реагирования | Ранжирование по аналогам и правилам безопасности; решение принимает человек |
| Документы | Четыре редактируемых DOCX из локальных шаблонов |
| Согласование | Черновик → На проверке → Утверждено → Готово к доведению; история изменений в SQLite |

> **Данные учебные.** Начальный датасет и исторические случаи синтетические. Качество ML на реальных происшествиях не доказано, а сходство случаев не доказывает эффективность меры. Никакое решение не применяется автоматически.

## Быстрый запуск

### Windows — CMD

1. Скачайте проект через **Code → Download ZIP** на GitHub и распакуйте архив. Откройте папку `marshrut-doc` — в ней должны быть `README.md` и `setup-windows.cmd`.
2. Установите [64-разрядный Python](https://www.python.org/downloads/windows/) (поддерживается Python 3.12–3.15). Откройте **новое** окно CMD и проверьте:

   ```bat
   python --version
   ```

3. Откройте папку `marshrut-doc` в Проводнике. Щёлкните по адресной строке, напишите `cmd` и нажмите Enter. В открывшемся окне выполните:

   ```bat
   setup-windows.cmd
   ```

   Дождитесь строки `Setup complete`. Скрипт создаст виртуальное окружение, установит зависимости и **обучит модель**. Если он выдал ошибку, дальнейшие шаги пока не выполняйте.

4. Откройте **ещё одно** окно CMD из той же папки и запустите:

   ```bat
   run-backend.cmd
   ```

5. Откройте в браузере **http://localhost:8000**. Окно с сервером оставьте открытым; для остановки нажмите `Ctrl+C`.

При следующем запуске достаточно выполнить только шаги 4–5. PowerShell тоже подойдёт, но команды из этой инструкции рассчитаны на CMD. Если вы используете PowerShell, запускайте файлы как `.\setup-windows.cmd` и `.\run-backend.cmd`.

### macOS / Linux — Terminal

1. Скачайте ZIP проекта с GitHub, распакуйте его и установите [Python 3.12 или новее](https://www.python.org/downloads/) (на Linux также нужен модуль `venv` вашего дистрибутива). Проверьте: `python3 --version`.
2. Откройте Terminal в папке `marshrut-doc`. Например, если папка находится в «Загрузках»:

   ```bash
   cd ~/Downloads/marshrut-doc
   ```

   Если папка называется иначе, перетащите её из Finder/файлового менеджера в Terminal после команды `cd `.
3. Выполните настройку один раз:

   ```bash
   bash setup-unix.sh
   ```

   Дождитесь `Готово`. Скрипт установит зависимости в отдельное окружение и обучит модель.
4. Запустите сервер:

   ```bash
   bash run-unix.sh
   ```

5. Откройте **http://localhost:8000**. Для остановки сервера нажмите `Ctrl+C`. При следующих запусках повторяйте только шаг 4.

**Не нужен `npm` для запуска готового проекта.** Он используется только при изменении React-интерфейса.

## Как работать

1. **Сообщение.** Опишите происшествие; место, маршруты и время можно уточнить позже. Нажмите «Посмотреть варианты».
   Рядом с полем «Где?» можно открыть Яндекс Карту, найти город, выбрать точку и применить найденный адрес. Ключ уже указан в проекте; вводить его в интерфейсе не нужно. Текст адреса можно исправить вручную; точка сохраняется вместе с ним, пока вы не нажмёте «Убрать точку». В разделе решения карта также доступна при исправлении сообщения.
2. **Варианты.** Проверьте тип происшествия, оценки пяти классов, три похожих учебных случая и ограничения мер. Выберите меру для проверки.
3. **Решение.** Подтвердите безопасность и условия движения, укажите сроки и ответственного. Пройдите статусы согласования вручную.
4. **Документы.** Заполните реальные реквизиты организации, проверьте и при необходимости отредактируйте текст. Скачайте DOCX. Инструкция водителю при изменении трассы блокируется до подтверждения схемы, трассы и остановок.

Кнопка отправки выполняет **только локальную симуляцию**: документы никому не отправляются.

Для карты нужен интернет. В рабочей копии ключ указан в `frontend/public/map-config.js` и включён в готовую сборку как `frontend/dist/map-config.js`. Оба файла исключены из Git через `.gitignore`; в репозитории оставляйте только `frontend/public/map-config.example.js` без ключа. После клонирования скопируйте шаблон в `frontend/public/map-config.js`, вставьте свой ключ и выполните `npm run build` из папки `frontend`. Для уже собранного приложения можно создать `frontend/dist/map-config.js` напрямую, не пересобирая интерфейс. Ключ будет виден в браузере при работе карты: ограничьте его по HTTP Referer в кабинете Яндекса. Если файлы с ключом ранее уже попали в Git, одного `.gitignore` недостаточно: уберите их из индекса командой `git rm --cached -- frontend/public/map-config.js frontend/dist/map-config.js`; если ключ был опубликован, замените его в кабинете Яндекса. Ключу нужны активные продукты **JavaScript API** и **API Геокодера**. Для локального запуска укажите в HTTP Referer `localhost` без схемы и порта, откройте приложение через `http://localhost:8000` (при запуске Vite — через `http://localhost:5173`). После настройки статус JavaScript API должен стать «Активен»; это может занять до 15 минут. Если карта недоступна, адрес можно ввести вручную.

## Что в проекте действительно является ML

| Часть | Реализация | Ограничение |
| --- | --- | --- |
| Классификатор | `backend/app/ml.py`: `TfidfVectorizer` + `LogisticRegression`, реальный `fit()`, `joblib`; оценки классов и признак низкой уверенности | 120 синтетических текстов, 60 групп сценариев; качество на реальных сообщениях пока неизвестно |
| Похожие случаи | `backend/app/service.py`: TF-IDF по локальным случаям и косинусное сходство | Это сходство текстов, не оценка успеха меры |
| Меры | `backend/app/service.py`: сумма сходства аналогов, небольшие поправки по длительности и жёсткие проверки условий | **Не** обученная модель эффективности; при нехватке данных нужно решение специалиста |

При проверке классификатора одинаковые сценарии и близкие перефразирования объединяются в группы **до** разделения на обучающую и отложенную выборки. В разделе «Модель и учебные данные» видны число примеров, версия, результаты проверки и матрица ошибок. Датасет мал: эти метрики нельзя переносить на реальные условия.

Можно загрузить CSV UTF-8 со столбцами `text,label`; рекомендованы также `scenario_group,source`. Категории должны точно совпадать с категориями интерфейса. После загрузки нажмите **«Переобучить модель»**: это запускает настоящее обучение и сохраняет новую модель. Образец CSV скачивается в интерфейсе.

## Документы

Шаблоны учитывают [ГОСТ Р 7.0.97-2025](https://protect.gost.ru/gost/details/360994e3-9a70-47b9-ab3a-cf21809e26ed) об организационно-распорядительной документации: А4, поля, шрифт, интервалы, расположение адресата и подписи. Стандарт регулирует оформление, но **не содержит готового текста** распоряжения на случай сбоя транспорта. Поэтому тексты — проекты для проверки специалистом. Неизвестные дату, номер, организацию и подпись программа оставляет в квадратных скобках. Для официального выпуска нужны утверждённый бланк организации, реальные реквизиты и подпись уполномоченного лица.

## Для разработчика

| Компонент | Технологии | Путь |
| --- | --- | --- |
| Интерфейс | React, TypeScript, Vite, Tailwind, локальные UI-компоненты | `frontend/src/` |
| Готовая сборка | Статические файлы, которые отдаёт FastAPI | `frontend/dist/` |
| API и документы | FastAPI, python-docx, SQLite | `backend/app/` |
| Модель | scikit-learn, pandas, numpy, joblib | `backend/app/ml.py` |
| Тесты | unittest и FastAPI TestClient | `backend/tests/` |

Если меняете интерфейс, установите [Node.js LTS](https://nodejs.org/en/download/) и выполните:

```bash
cd frontend
npm ci
npm run dev
```

Для обновления сборки, которую отдаёт Python-сервер: `npm run build`. Изменения в `frontend/dist/` нужно включить в Git-коммит. API доступен по адресу `http://127.0.0.1:8000/docs`.

Проверка backend (тестовый клиент устанавливается отдельно):

```bash
cd backend
.venv-unix/bin/python -m pip install -r requirements-dev.txt
.venv-unix/bin/python -m unittest discover -s tests -v
```

На Windows в CMD замените `.venv-unix/bin/python` на `.venv-win\Scripts\python.exe` в обеих командах.

Рабочие файлы `backend/data/classifier.joblib`, `model_meta.json` и `incidents.sqlite3` создаются локально при настройке и не должны попадать в Git. На другом компьютере выполните настройку заново. В архиве для демонстрации может присутствовать обученная модель; скрипт настройки всё равно переобучает её в вашем окружении.

## Если что-то не запускается

| Сообщение | Что сделать |
| --- | --- |
| `python` / `python3` не найден | Установите Python, откройте новое окно терминала и проверьте версию |
| Ошибка установки pandas | Убедитесь, что используется Python 3.12–3.15, и запустите скрипт настройки заново; он выбирает совместимую версию pandas |
| `npm` не найден | Для обычного запуска это не ошибка: запускайте `run-backend.cmd` или `run-unix.sh` |
| Порт `8000` занят | Закройте прежнее окно сервера через `Ctrl+C`, затем запустите сервер снова |
| Изменён интерфейс, но в браузере старая версия | Выполните `npm run build` в `frontend`, затем обновите страницу |
